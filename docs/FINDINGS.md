# Реестр находок ревью 2026-09-03

Ревью по ролям (B — деньги, C — данные) плюс собственная проверка ролей A и
D. Каждая находка перепроверена чтением кода: отчёт агента — гипотеза.

Файл существует ради одного: находка без записи теряется. Строка «сделано»
ставится ТОЛЬКО когда есть тест и мутация, которая его роняет.

## Открыто — по убыванию ущерба

### 6. `close_stale_open_trades` уничтожает отложенный повтор учёта
`core/db.py`, вызов `strategy/trader.py`. Блок закрытий во время простоя при
неподтверждённом closed-pnl делает `continue` с обещанием «повтор на
следующем тике». В ТОМ ЖЕ тике строка помечается `stale`, а следующий тик
ищет только `status='open'`. Следующего тика для неё не существует, и
реализованный убыток навсегда выпадает из дневного предохранителя.
Самоисцеление в `save_trade_close` существует (`status IN ('open','stale')`),
но недостижимо. Тестов на функцию нет ни одного.

### 7. Закрытая позиция навсегда занимает слот
`strategy/trader.py`. `_settle_closed_position` возвращает `False` и когда
записи ещё нет, и когда её не будет никогда (ордер не залился; гео-блок
closed-pnl). Вызывающий делает `continue` без `_forget_symbol` — по замыслу,
чтобы повторить. Но повторять нечего: слот из `MAX_POSITIONS` занят навсегда,
три таких символа тихо выключают автоторговлю.

### 8. Миграция ярлыка необратимо клеймит прошлую историю
`core/db.py`. `UPDATE signals SET strategy = ? WHERE strategy IS NULL` идёт на
каждом старте с ТЕКУЩИМ `STRATEGY_ID`. Естественный сценарий «перехожу на
новую стратегию, ставлю новый ярлык» проставляет новый ярлык 40 старым
исходам. Откатить нельзя: `NULL` больше нет.

### 9. Несовпадение ярлыка обнуляет счётчики без признака, что данные есть
`core/db.py`. Сравнение регистрозависимое, `STRATEGY_ID` не нормализуется.
Опечатка в регистре обнуляет карточку, срезы и прогресс замера
одновременно, а `history_span()` показывает те же строки. Экран говорит
«данные есть, статистики нет» — неотличимо от «стратегия новая».

### 10. Счётчик замера двигается ползунком на дашборде
`core/db.py` фильтрует по `cfg.TRADE_MIN_SCORE` на момент ЗАПРОСА, а порог
меняется через `POST /api/settings` в рантайме. Правило остановки задано
числом (130), значит счётчик обязан быть монотонным. Сейчас сдвиг ползунка
переписывает уже собранное задним числом, а после рестарта откатывается.

### 11. Детектор опечаток слеп к переменной, чья опечатка воспроизводит баг №1
`core/config.py`. В списке известных имён есть `PROXY_URL`/`PROXY_LIST`,
которых в коде нет вовсе; отсутствуют реально читаемые
`WEBSHARE_API_TOKEN`, `BYBIT_PROXY`, `BYBIT_PROXY_2`, `BYBIT_BASE_URL`.
Опечатка в токене прокси = нет прокси = гео-блок = проверка стопа
прекращается.

### 12. «Opened» рапортуется по позиции с нулевым объёмом
`strategy/trader.py`. При полном закрытии сокращением `qty = 0.0`, но
выполнение доходит до `log.info("Opened ... qty=0.0")` и возвращает `True`.
Строка в `trades` сохраняет ИСХОДНЫЙ объём — разбор в R по таблице смещён
для любой сокращённой позиции.

### 13. Отказ сокращения оставляет риск выше 3% и только пишет в лог
`strategy/trader.py`. Обе ветки отказа оставляют позицию жить, вход
возвращает `True`. Инвариант «потолок 3% жёсткий» превращается в «жёсткий,
если сокращение прошло». `_RISK_WARNED` печатает CRITICAL один раз за жизнь
позиции — при отсутствии алертинга это ноль внимания.

### 14. Отказ ордера с «обычным» кодом снимает слот, не спросив биржу
`strategy/trader.py`. Ветка потерянного ответа устроена правильно: идёт в
`get_position`. Соседняя ветка любой `retCode != 0` (кроме 110072) считает
доказательством, что позиции нет, без чтения биржи. Если позиция всё же
возникла — она останется без строки в `trades`, монитор усыновит её как
MANUAL, а ручным стоп не досылается. Буквальный рецидив бага №1.
PLAUSIBLE: нужен реальный код ответа Bybit, при котором ордер принят и
отвечено ошибкой.

### 15. Лимит по числу строк не покрывает нерешённые
`core/db.py`. После отмены удаления решённых по возрасту нерешённые
чистятся только по возрасту (144 ч), потолка по числу у них нет. При
стоящем оценщике это до ~14 000 строк против `MAX_SIGNALS_DB` = 5000.
Заявленный потолок базы перестал быть потолком. Заодно устарело описание
в `docs/REVIEW.md §2`.
