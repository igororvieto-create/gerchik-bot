# Поиск сигнала в собранных признаках — результат

Пункт 1 плана: не гадать правила по одному, а спросить данные разом —
существует ли комбинация уже записываемых признаков, отделяющая выигрыш
от проигрыша.

## Что проверено

1389 решённых исходов (8 месяцев, 60 монет, дампы Binance).

Признаки: score, sl_pct, atr_pct, sl_atr, headroom, confidence, round_pos.
Каждый разбит на квартили — 28 проверок. Плюс 8 комбинаций двух
признаков, устойчивых в обоих прогонах. Итого около 36 проверок.

`mfe_r` из признаков ИСКЛЮЧЁН: он известен только постфактум, это было
бы заглядыванием в будущее.

## Планка (из docs/PREREGISTRATION.md)

ev_r > 0.10, n >= 100, нижняя граница интервала Уилсона выше безубытка
(34.3% при среднем стопе 4.48%).

## Результат

| Лучшее найденное | n | ev_r | Винрейт | CI95 |
|---|---|---|---|---|
| atr_pct >= 5.13 | 313 | +0.006 | 34.2% | 29–40% |
| atr_pct >= 5.13 + sl_atr < 1.01 | 161 | +0.075 | 36.6% | 30–44% |
| atr_pct >= 3.73 + sl_atr < 0.75 | 48 | +0.154 | 39.6% | 27–54% |

**Ни одна корзина планку не проходит.** У всех с достаточным n нижняя
граница интервала ниже безубытка; у той, что выше по ev_r, n=48.

Найти одну маргинально положительную корзину среди 36 проверок — ровно
то, что даёт шум (LITERATURE §6).

## Вывод

**В признаках, которые бот записывает, эксплуатируемого сигнала нет.**

Это закрывает целый класс попыток: подкручивать правила, построенные на
этих же признаках, бессмысленно — отделять победы от поражений ими
нечем. Нужны ДРУГИЕ данные или другой продукт, а не другая настройка.
